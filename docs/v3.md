# The plugin and the CLI on Agentic ID V3

This page is for people working on the plugin or the CLI.

## How it fits together

```
Claude Code plugin ── Streamable HTTP + OAuth ──> https://onesource-v3.icustomer.ai/mcp   (hosted; agentic-id-v3 apps/edge)
terminal ── cli/agentic-id ──> cli/lib/operations.mjs ─> cli/lib/client.mjs ── HTTPS ──> V3 API  /v1/*
                                (clean, refuse, cap, batch)  (Bearer key or sign-in, problem+json)
```

Since 0.7.0 the Claude Code plugin runs nothing on the user's computer: no local MCP server, no
hooks, no bundled scripts. It is Markdown and JSON pointing at the hosted MCP server, which is what
Claude's plugin directory accepts from an organization that is not Verified. The hosted tools are
defined in `agentic-id-v3` (`libs/mcp-tools`). The CLI keeps the local guards, CSV handling,
estimates and batching, and is published to npm on its own.

| File | Job |
| --- | --- |
| `cli/lib/client.mjs` | One method per V3 route. Errors become `{ error, message, fix }`. A 429 is retried once; a paid POST is never replayed on a server error or timeout |
| `cli/lib/guards.mjs` | Input cleaning. Personal emails and phones are dropped here |
| `cli/lib/estimate.mjs` | The rate card and the worst-case cost of a call |
| `cli/lib/operations.mjs` | What each command does: clean, refuse locally, set the cap, batch, merge answers, add `input_notes` |
| `cli/lib/csv.mjs` | CSV reader and writer, column detection |
| `cli/lib/shield.mjs` | Keeps data-source names and bills out of answers |
| `cli/cli.mjs`, `cli/agentic-id` | The CLI |

## Run it against a local V3

In the `agentic-id-v3` repo, start the service and the edge API. Then either sign in or create a key.

Sign in (the API must have sign-in on; for a login page that needs no account, that repo has a
stand-in, `apps/edge/test/fake-fusionauth.mjs`):

```bash
export AGENTIC_ID_URL=http://localhost:3100
cli/agentic-id login
```

Or create a key:

```bash
pnpm --dir apps/edge keys create --workspace ws_plugin_dev --name plugin-tests
```

Keep the key in a file outside any repository (mode 600) and point the tests at it:

```bash
export AGENTIC_ID_URL=http://127.0.0.1:3100
export AGENTIC_ID_API_KEY_FILE=~/.agentic-id-dev/key
```

## Tests

| Command | What it covers | Needs |
| --- | --- | --- |
| `./test/validate.sh` | Manifests, frontmatter, secrets scan, directory checks, eval suite shape, all unit tests | nothing |
| `node --test test/v3-unit.test.mjs` | Guards, estimates, CSV, operations against a fake client, the HTTP client against a local stub, the CLI | nothing |
| `./test/e2e.sh` | A headless Claude Code session with the plugin loaded as installed, against the hosted server | a `/mcp` sign-in to the plugin's server, the `claude` CLI, about $1 of model spend |
| `./test/evals.sh` | Skill triggering and behaviour, with mocked tools | the `claude` CLI, up to $10 of model spend |

## Edge cases the CLI handles before a call is made

| Input | What happens |
| --- | --- |
| `Jane Doe <Jane.Doe@Acme.io>`, `mailto:` links, trailing punctuation, zero-width characters | Cleaned to the bare address |
| The same address twice, in any case | Checked and paid once |
| gmail.com and other personal mailboxes | Held back, reported as `rejected` with `checked: locally` |
| A phone number, in a phone column or in the name column | Dropped and reported |
| `https://www.acme.io/about?x=1`, `ACME.IO.` | Cleaned to `acme.io` |
| A mail provider given as the company domain | Refused: not a company |
| LinkedIn links with tracking parameters or country subdomains | One canonical profile URL |
| Sales Navigator, Recruiter and company-page links given for a person | Refused with the reason |
| A name with no company | Refused: many people share it |
| `UK`, `USA` | Sent as `GB`, `US` |
| `employees_min` above `employees_max` | Refused |
| A person search with no title or seniority | Refused |
| `job_title`, `email`, `employee_size` as enrich fields | Mapped to `title`, `work_email`, `employees` |
| Phone fields in enrich | Refused |
| More than 1,000 emails, more than 100 contacts | Sent in batches inside one cap; stops when the cap is reached |
| A call that could cost more than 10 credits with no `max_credits` | Refused with the estimate |
| An argument the tool does not have (`role` for `roles`) | Refused with the allowed names |
| Semicolon or tab separated CSV, a BOM, quoted newlines | Read correctly |
| CSV cells starting with `=`, `+`, `-`, `@` | Written with a leading quote so a spreadsheet does not run them |
| Out of credits, a bad key or an outage in the middle of a list | The run stops instead of failing every remaining row |

## Not there yet

- **Hosted tools the old local server had.** The hosted MCP server has no batch resolve, workspace
  (credits and spend), estimate or CSV-file tool. The plugin's skills send those jobs to the CLI.
- **New accounts verifying their email.** A person who signs up on the sign-in page and has not
  verified their email is refused; the email-code pages from the v2 server are not ported.
- **Readable contact values.** The V3 API always asks the service for masked values, so emails
  come back masked whatever the caller's scopes.
- **Monitoring and ad-audience match.** The V3 service has them; its public API has no routes for
  them, so the plugin has no tools for them.
- **Exactly-once across a lost connection inside the API.** A keyed call is answered from its
  first result, but if the API loses the service mid-call the key frees after six minutes and a
  later retry could repeat the work.
